# 모집설정 단일 행 정책

모집설정은 사이트 전체가 함께 사용하는 한 묶음의 설정입니다. **같은 사이트에 서로 다른 모집설정 행이 생기지 않도록** DB와 저장 액션이 고정 키를 사용합니다. `singleton`은 이렇게 하나의 설정만 유지한다는 뜻입니다.

## 현재 규칙

`recruitment_settings.singleton_key`는 항상 `1`입니다. CHECK 제약은 키가 1인지 검사하고, UNIQUE 제약은 같은 키를 두 행에 저장하지 못하게 합니다. 이 두 제약은 행이 두 개 생기는 것을 막으며, 삭제된 기본 행을 스스로 복구하는 예약 작업은 아닙니다.

관리자 전체 설정·현재 모집 정보·포스터·세부 안내 저장은 이 키에 `INSERT ... ON CONFLICT DO UPDATE`를 사용합니다. 즉, 설정이 없으면 만들고 이미 있으면 갱신합니다. 섹션별 저장은 해당 섹션의 컬럼만 갱신합니다. 같은 섹션을 여러 사람이 편집할 때에는 마지막 저장 결과를 함께 확인합니다.

## 설치 계획과 기존 DB 전환

`npm run db:migrate-recruitment-singleton`은 `.env` 없이 **접속 없는 설치 계획**만 출력합니다. `--confirm-apply`도 신뢰된 대상·복구·승인 경계가 없어 접속 전에 차단합니다. 다른 인자나 환경 플래그·자체 승인 JSON으로 직접 적용을 열 수 없습니다.

기존의 복수 행 사전 조회, 컬럼·제약·기본행 결합 설치와 사후 단일 행 검증은 비활성입니다. 기본행 SQL은 같은 파일의 순수 문자열 `recruitmentDefaultInsertSql`로 보존해 선언 소유자와 독립 신규 설치 검증의 근거를 유지합니다. 모듈 import나 공개 CLI는 이 문장을 실행하지 않습니다. 상수·소유 로컬 PostgreSQL 회귀·신규 설치 후보의 보존을 기존 DB 결합 업그레이드의 검증이나 운영 승인으로 사용하지 않습니다.

실제 적용은 [DB 변경 절차](developer/database-change-procedure.md)와 [#280](https://github.com/yeongseon/hra-website/issues/280)의 대상·백업/복구·승인이 검증된 업그레이드 경로가 마련된 뒤 진행합니다. 다음은 해당 검토에서 확인할 조건이며, 현재 CLI는 DB를 조회해 행 수를 판정하지 않습니다.

| 기존 행 수 | 별도 승인된 업그레이드에서 확인할 조건 |
| --- | --- |
| 0개 | 기본행과 제약의 준비 순서, 키 1인 설정 한 행 확인 |
| 1개 | 기존 ID·편집 콘텐츠를 보존하고 단일 행과 두 제약 확인 |
| 2개 이상 | 모든 섹션의 보존 값을 수동 결정하기 전 적용 보류 |

여러 행이 있으면 `updated_at` 최신 행, 동률이면 ID 역순을 우선 검토합니다. 이 순서는 정본을 자동 결정하는 규칙이 아닙니다. 각 행의 포스터·일정·안내를 비교해 보존할 값을 결정하고 검토된 정리 절차를 마련합니다. 현재 CLI는 행을 조회·삭제·병합하지 않습니다.

**현재 명령의 정상 결과:** 설치 계획과 접속·변경이 없다는 안내입니다. 이 결과는 DB 준비 완료를 뜻하지 않습니다. 직접 적용 거부를 인자나 운영 환경값으로 우회하지 말고 승인된 업그레이드 경로를 먼저 준비합니다. 필요한 객체가 없는 DB에는 해당 제약을 전제로 하는 앱 기능을 배포하지 않습니다.

## 과거 적용 기록

2026-10-14 운영 DB는 기존 행이 1개였고, 적용 후에도 1개와 두 제약이 확인됐습니다. 이 기록은 당시 대상의 결과이며 2026-10-18 현재 모든 환경을 다시 확인한 증거는 아닙니다.
