# 모집설정 단일 행 정책

모집설정은 사이트 전체가 함께 사용하는 한 묶음의 설정입니다. **같은 사이트에 서로 다른 모집설정 행이 생기지 않도록** DB와 저장 액션이 고정 키를 사용합니다. `singleton`은 이렇게 하나의 설정만 유지한다는 뜻입니다.

## 현재 규칙

`recruitment_settings.singleton_key`는 항상 `1`입니다. CHECK 제약은 키가 1인지 검사하고, UNIQUE 제약은 같은 키를 두 행에 저장하지 못하게 합니다. 이 두 제약은 행이 두 개 생기는 것을 막으며, 삭제된 기본 행을 스스로 복구하는 예약 작업은 아닙니다.

관리자 전체 설정·현재 모집 정보·포스터·세부 안내 저장은 이 키에 `INSERT ... ON CONFLICT DO UPDATE`를 사용합니다. 즉, 설정이 없으면 만들고 이미 있으면 갱신합니다. 섹션별 저장은 해당 섹션의 컬럼만 갱신합니다. 같은 섹션을 여러 사람이 편집할 때에는 마지막 저장 결과를 함께 확인합니다.

## 적용 방법과 결과

`npm run db:migrate-recruitment-singleton`은 **DB를 변경하는 명령**입니다. 실행 전에 [DB 변경 절차](developer/database-change-procedure.md)에 따라 대상과 백업을 확인하고 격리 DB에서 먼저 검증합니다. 이 스크립트에는 `--confirm-apply` 확인 단계가 없습니다.

| 기존 행 수 | 스크립트 동작 | 확인할 결과 |
| --- | --- | --- |
| 0개 | 기본 행 생성 | 키 1인 설정 한 행과 두 제약 |
| 1개 | 기존 ID와 값을 보존하고 제약 준비 | 같은 설정 한 행과 두 제약 |
| 2개 이상 | 변경 전에 중단 | 담당자가 모든 섹션을 비교할 때까지 적용 보류 |

여러 행이 있으면 `updated_at` 최신 행, 동률이면 ID 역순을 우선 검토합니다. 이 순서는 정본을 자동 결정하는 규칙이 아닙니다. 각 행의 포스터·일정·안내를 비교해 보존할 값을 결정하고 검토된 정리 절차를 거친 뒤 재실행합니다. 스크립트는 중복 행을 삭제하지 않습니다.

**정상 결과:** `모집설정 단일 행 제약과 기본 행이 준비되었습니다.`가 표시됩니다. **실패하면:** 대상 DB와 오류 원인을 확인하고 재실행 여부를 결정합니다. 성공 메시지만으로 다른 환경에도 적용됐다고 판단하지 않습니다.

## 과거 적용 기록

2026-10-14 운영 DB는 기존 행이 1개였고, 적용 후에도 1개와 두 제약이 확인됐습니다. 이 기록은 당시 대상의 결과이며 2026-10-18 현재 모든 환경을 다시 확인한 증거는 아닙니다.
