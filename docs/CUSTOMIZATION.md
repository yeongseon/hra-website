# HRA 화면과 콘텐츠 수정하기

화면을 바꾸기 전에 **관리자가 저장하는 데이터인지, 개발자가 배포하는 UI인지** 구분합니다. 관리자 화면에서 바꿀 수 있는 제목·사진을 소스 파일에서 찾으면 실제 데이터가 바뀌지 않을 수 있습니다.

문서 확인일: 2026-10-18. 아래 경로는 현재 `src/` 구조를 기준으로 합니다. 향후 `apps/web` 전환은 [플랫폼 아키텍처](developer/platform-architecture.md)의 계획이며, 아직 존재하지 않는 경로를 현재 수정 위치로 사용하지 않습니다.

## 1. 어디에서 수정할까요?

| 바꾸려는 내용 | 먼저 열 곳 | 이유 |
| --- | --- | --- |
| 교수 소개·사진, 기수 정보 | 관리자 화면 | DB 데이터이므로 소스 수정 불필요 |
| 공지·갤러리·수료생 이야기 | 관리자 화면 | 저장된 콘텐츠를 수정 |
| 모집 날짜·포스터·외부 링크 | 모집 설정 | 현재 모집 설정을 수정 |
| 지원서 질문·공개 여부 | 지원서 관리 | 내부 접수 규칙과 연결 |
| 메뉴 위치·화면 구성·색상 | 해당 UI 소스 | 배포할 코드의 변경 |
| 로그인 방식·권한 | 인증·인가 설계와 담당자 | 문구 변경과 다른 기능 변경 |

운영 콘텐츠는 [관리자 가이드](ADMIN-GUIDE.md), 개발용 파일 수정은 아래 순서로 진행합니다.

## 2. 화면에서 소스까지 찾아가기

컴포넌트는 화면의 한 부분을 만드는 코드입니다. `page.tsx`는 여러 컴포넌트를 조합할 수 있으므로 찾는 제목이 항상 페이지 파일 안에 있는 것은 아닙니다.

| 화면 | 시작할 파일·폴더 |
| --- | --- |
| 홈페이지 | `src/app/(public)/page.tsx`와 `_components/hero-section.tsx`, `stats-section.tsx` |
| 소개 | `src/app/(public)/about/page.tsx` |
| 커리큘럼 | `src/app/(public)/curriculum/page.tsx`와 여기서 가져오는 컴포넌트 |
| 기수 소개 | `src/app/(public)/cohorts/page.tsx`; 기수 값 자체는 관리자 화면 |
| 공개 상단 메뉴 | `src/components/layout/header.tsx`의 `navItems` |
| 하단 영역 | `src/components/layout/footer.tsx` |
| 모집 안내 | `src/app/(public)/recruitment/page.tsx`와 `_components/` |
| 로그인 문구·폼 | `src/app/(auth)/login/login-form.tsx` |
| 로그인 제공자 전달 | `src/app/(auth)/login/page.tsx` |
| 관리자 메뉴 | `src/app/(admin)/admin/admin-shell.tsx`의 `navItems` |
| 공통 스타일 | `src/app/globals.css`, 공통 UI 컴포넌트 |

파일 이름은 프로젝트 안의 위치를 나타냅니다. VS Code의 전체 검색으로 실제 문구를 찾습니다. 별도 검색 도구인 ripgrep이 설치되어 있다면 다음 `rg` 명령도 사용할 수 있습니다. 아래는 예시이며 운영 데이터를 조회하지 않습니다.

```bash
rg -n '찾을 화면 문구' src/app src/components
```

검색 결과가 없다면 DB에서 읽는 값인지 확인합니다. 통계 숫자도 고정 문자열인지 조회 결과인지 먼저 살피고, 화면의 숫자만 임의로 바꾸지 않습니다.

## 3. 작은 문구 변경부터 확인하기

JSX는 HTML과 비슷한 모양으로 화면을 작성하는 문법입니다. 다음은 원리를 보여 주는 예시이며 특정 파일의 현재 내용을 그대로 옮긴 것은 아닙니다.

```tsx
<h1>기존 안내 문구</h1>
```

태그 사이의 문구를 바꾸면 표시 문구가 달라집니다. `{...}`에는 코드 표현식이 들어갈 수 있고, 따옴표는 문자열 범위를 나타냅니다. 필요한 한 부분만 수정하고 저장 후 로컬 화면과 코드 오류를 확인합니다.

메뉴 항목의 `label`은 표시 이름, `href`는 이동할 주소입니다. 메뉴를 추가하려면 실제 페이지가 존재하고 해당 역할이 접근할 수 있어야 합니다. 메뉴 항목을 지워도 페이지나 서버 권한 검사가 삭제되는 것은 아닙니다.

## 4. 화면별로 놓치기 쉬운 부분

### 홈페이지·기수

홈페이지의 큰 제목과 통계는 별도 컴포넌트로 나뉩니다. 기수 소개의 모집 상태·기간 등은 DB에서 오는 값인지 확인합니다. 표시된 '마감' 문구만 바꾸어 접수 기능을 제어하지 않습니다.

### 모집 안내·지원서

모집 날짜와 내부 양식 공개는 다른 설정입니다. 화면 수정 시 둘의 동작을 묶지 않습니다. [모집 접수 정책](recruitment-intake-policy.md)에 맞춰 안내 문구도 유지합니다.

### 로그인·메뉴

로그인 화면의 문구와 버튼 배치는 수정할 수 있지만, 제공자 활성화 여부는 서버 설정에서 전달합니다. 버튼을 강제로 표시하는 것으로 로그인 설정을 대신하지 않습니다. 메뉴 노출과 서버의 접근 검사를 함께 고려합니다.

### 이미지·링크

콘텐츠 사진은 관리자 업로드 기능을 사용합니다. 새 외부 이미지 도메인을 쓰려면 `next.config.ts` 및 해당 콘텐츠의 허용 정책을 함께 확인합니다. 이미지를 보이게 하려고 모든 도메인을 허용하거나 공개 URL을 보호 자료의 대체 경로로 사용하지 않습니다.

### 색상·배치

이 프로젝트는 Tailwind CSS v4를 사용합니다. 공통 색상과 여백을 먼저 확인하고 비슷한 화면의 패턴을 재사용합니다. 모바일 폭과 키보드 이동에서도 글자·버튼·초점 표시가 보이는지 확인합니다. 새 Tailwind 설정 파일이 필요하다고 가정하지 않습니다.

## 5. 변경 후 확인 순서

1. 작업 브랜치에서 작은 범위만 수정합니다.
2. `npm run dev`로 로컬 화면을 열고 변경한 곳을 확인합니다.
3. 문구 길이·줄바꿈·모바일 표시·링크 이동을 검사합니다.
4. 코드 변경이라면 아래 검사를 수행하고 관련 테스트를 확인합니다.
5. PR에서 바꾼 목적과 확인한 결과를 설명하고 Preview를 검토합니다.

```bash
npm run lint
npm run typecheck
npm run build
```

**정상 결과:** 검사에 통과하고 실제 화면에서도 의도한 내용이 보입니다. **실패하면:** 오류가 가리키는 변경부터 수정합니다. 경고나 실패를 숨기려고 검사 설정·훅을 끄지 않습니다.

소스 변경은 저장만으로 운영에 반영되지 않습니다. Preview·리뷰·운영 반영은 [배포 가이드](DEPLOYMENT.md)를 따릅니다. `git add .`로 무관한 파일까지 모아 올리기 전에 실제 변경 목록을 확인합니다.
