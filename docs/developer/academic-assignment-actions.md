# 과제 생성·수정·공개·종료 서버 계약

과제 관리 화면을 수정하거나 서버 저장 로직을 바꿀 때 읽는 문서입니다. **서버 액션**은 화면에서 호출하더라도 서버에서 실행하는 함수입니다. 이 문서의 **계약**은 누가 어떤 입력을 보낼 수 있고, 저장 결과와 오류가 무엇인지 정한 규칙입니다.

사용자 흐름은 [과제 관리 화면](academic-assignment-admin.md)에서 먼저 확인하고, DB 제약을 바꾼다면 [과제 스키마 적용](academic-assignments-migration.md)을 함께 읽습니다. 아래 서비스와 액션은 구현되어 있으며, 운영 DB 적용·기능 활성화 여부는 별도 운영 기록으로 확인해야 합니다. 공통 용어는 [용어집](../getting-started/glossary.md)을 참고합니다.

#149는 지정된 G1 운영 책임자의 과제 관리 서비스와 서버 액션을 제공합니다.
홈페이지 ADMIN 역할만으로 승인하지 않으며 실제 로그인 계정이 `ACADEMIC_APPROVER_USER_ID`와 일치해야 합니다.
지정된 MEMBER·FACULTY·ADMIN 계정은 허용하고 PENDING은 거부합니다.
조회와 변경 모두 `ACADEMIC_ENABLED=true`가 필요합니다. 기본 비활성 상태에서는 DB를 호출하지 않습니다.
변경에는 `ACADEMIC_ENROLLMENT_WRITES_ENABLED=true`도 필요합니다. #142 정책 확정과 운영 승인 전에는 비활성으로 유지합니다.

## DB 준비와 검증

별도 격리 DB에서 다음 순서로 범위 SQL을 적용합니다.

1. `scripts/migrate-academic-students.sql` (#144)
2. `scripts/migrate-academic-assignments.sql` (#147)
3. `scripts/migrate-academic-assignment-actions.sql` (#149)

세 번째 SQL은 `academic_assignment_events`와 `mutate_academic_assignment`만 추가합니다.
반복 적용 시 컬럼·기본값·FK·CHECK 구조를 확인하며 다른 기존 구조를 자동 보정하지 않습니다.
운영 적용은 백업·복구 경로, 카탈로그, 격리 테스트를 확인한 별도 배포 절차로 진행합니다.
전체 `db:push`가 공개 트리거·범위 함수를 대신하지 않습니다.

## 서버 서비스와 액션

`src/features/academics/assignments/service.ts`와 `actions.ts`는 다음 함수를 제공합니다.

| 함수 | 입력 | 결과 |
| --- | --- | --- |
| `createAssignment` | 요청 ID, 기수·제목·안내·선택 수업·마감 | 새 DRAFT 또는 같은 요청의 기존 과제 |
| `updateDraftAssignment` | 생성 입력과 과제 ID, `expectedUpdatedAt` | 현재 버전이 일치하는 DRAFT 수정 |
| `publishAssignment` | 요청 ID, 과제 ID, 초안 버전, 대상 확인값 | 확인한 초안·명부의 최초 대상 스냅샷 |
| `closeAssignment` | 요청 ID, 과제 ID | PUBLISHED → CLOSED, 종료 재호출은 유지 |
| `listAssignmentsAdmin` | 선택 기수·상태·limit·offset | 지정 책임자의 과제 관리 목록 |

모든 변경의 `requestId`는 클라이언트에서 한 작업당 생성한 UUID이며 재시도에서는 유지합니다.
선택 `correlationId`가 없으면 requestId를 사용합니다. 로그인 주체는 입력으로 지정할 수 없습니다.
생성·수정 입력은 다음과 같습니다. UUID는 형식 설명용입니다.

```json
{
  "requestId": "10000000-0000-4000-8000-000000000001",
  "cohortId": "20000000-0000-4000-8000-000000000001",
  "title": "주차별 읽기 과제",
  "instructions": "지정된 자료를 읽고 과제를 제출해 주세요.",
  "scheduleEventId": null,
  "scheduleSessionId": null,
  "dueAtKst": "2027-01-31T23:59:59"
}
```

제목은 공백 제거 후 1~200자, 안내는 최대 50,000자입니다.
UUID·상태·페이지 크기와 알 수 없는 필드를 서버에서 검증합니다. 수업 세션만 지정할 수 없으며,
다른 기수의 수업이나 다른 수업의 세션은 #147 DB 가드가 거부합니다.

`dueAtKst`는 `YYYY-MM-DDTHH:mm` 또는 초를 포함한 한국시간 벽시계입니다.
유효하지 않은 날짜, 24시, 시간대 접미사, 존재하지 않는 윤일을 거부합니다.
서버의 로컬 TZ와 관계없이 +09:00을 적용해 UTC로 변환하고 `timestamptz`에 저장합니다.
초안은 마감 생략·과거 시각을 허용하지만 최초 공개는 DB가 잠금을 얻은 시점보다 미래인 마감이 필수입니다.

수정의 `expectedUpdatedAt`은 직전 조회 결과의 문자열을 그대로 전달합니다.
DB의 마이크로초 정밀도를 유지하므로 JavaScript Date로 왕복 변환하거나 잘라내지 않습니다.
버전이 다르면 덮어쓰지 않고 새로 조회하도록 거부합니다.

공개 입력도 `expectedUpdatedAt`과 `expectedTargetFingerprint`가 필수입니다.
대상 확인값은 미리보기의 유효 학적 UUID를 canonical 소문자 문자열로 오름차순 정렬하고
쉼표로 연결한 문자열의 UTF-8 SHA-256(소문자 64자리)입니다. 빈 명부는 빈 문자열을 해시합니다.
최초 공개 함수는 초안 버전을 검사한 뒤 실제 생성된 대상의 학적 ID로 같은 해시를 계산합니다.
명부가 달라지면 HRA09로 공개·대상·감사를 전부 롤백하며 미리보기 재확인을 요구합니다.
미리보기 이후 미래 등록이 유효해진 경우도 탐지합니다. 같은 요청의 성공 재시도는 최초 확인값을 그대로 보내야 합니다.

## 원자성·재시도·공개 불변성

실제 세션 인가 후 SQL 함수가 지정 계정과 현재 승인 역할을 재검증합니다.
과제 변경과 최소 감사 저장은 한 PostgreSQL 문장으로 확정하며 Neon HTTP 대화형 트랜잭션을 사용하지 않습니다.
같은 requestId·행위·내용 재시도는 기존 과제를 반환합니다. 같은 요청 ID의 다른 내용·행위·주체는 거부합니다.
재시도 응답의 과제는 현재 상태이며 처음 저장한 본문을 감사 테이블에 복제하지 않습니다.

최초 공개는 #147의 `publish_academic_assignment`를 호출합니다. 행 잠금과 명부 잠금 후 대상 학생을 원자 확정합니다.
대상 0명 공개도 허용하며 공개 후 추가 등록 학생은 대상에 소급 추가하지 않습니다.
같은 요청 또는 다른 요청으로 다시 공개해도 대상은 추가되지 않습니다.
종료 후 공개 재시도는 CLOSED와 원래 대상을 유지합니다.

공개 후에는 제출 여부에 관계없이 내용·기수·수업·마감·대상을 수정·삭제할 수 없습니다.
PUBLISHED → CLOSED만 허용하며 초안을 바로 종료할 수 없습니다.
기존 제출·업로드 모델(#148)에 의존하지 않고 #147의 더 강한 불변 규칙을 유지합니다.

감사에는 요청 ID, 과제·주체 ID, 행위, 이전·이후 상태, 상관 ID, 시각, 정규화된 입력의 SHA-256 요약만 저장합니다.
제목·안내·연락처·URL·증빙 원문은 복제하지 않습니다. 감사 저장 실패나 요청 중단은 과제·대상을 함께 취소합니다.
커밋 여부가 불명확하면 같은 요청 ID로 재시도합니다.

서버 액션은 한국어 결과만 반환하며 DB 오류 원문을 노출하지 않습니다.
예상하지 못한 실패도 고정 오류와 검증된 SQLSTATE·요청/상관 UUID만 서버 로그에 전달합니다.
Drizzle 오류의 원본 message·cause·SQL·params는 공통 로그 정제기에 넘기지 않습니다.
성공 시 관리 목록·상세·제출 현황과 학생 과제 목록·상세 경로를 갱신합니다. 실패 시 경로를 갱신하지 않습니다.
목록은 한 번에 기본 50건·최대 100건이며 학생 개인의 조회 계약은 별도 #150에서 구현합니다.
