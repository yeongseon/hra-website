# 지원서 질문 저장과 제출의 동시성 정책

질문·선택지 저장은 `save_application_form_questions` 단일 PostgreSQL 함수로 처리한다. 함수는 `application_forms` 행을 `FOR UPDATE`로 잠그고 `questions_revision`이 관리자 화면에서 읽은 값과 같은지 확인한다. 오래된 화면의 저장은 거부한다. 질문·선택지 변경과 버전 증가는 한 문장으로 확정되므로 중간 실패가 이전 내용을 바꾸지 않는다.

지원서 제출은 커밋된 질문·선택지만 한 번의 양식 조회로 읽는다. 저장 중에는 이전 질문·선택지 전체를 읽고, 저장 후에는 새 내용 전체를 읽는다. 제출 마스터의 양식 외래키는 저장 중의 양식 행 잠금이 풀릴 때까지 대기한다. 제출자가 이전 선택지를 읽고 저장이 끝난 뒤 답변을 쓰는 경우, 그 값은 제출 시 검증한 값으로 보존된다. 그 사이 질문이 삭제됐다면 답변 외래키가 제출을 거부한다.

제출 마스터·답변은 Neon HTTP 원자적 배치로 함께 저장한다 (#97). 답변 저장이 실패하면 UNIQUE 제약을 점유하는 마스터도 남지 않으므로 같은 이메일로 재시도할 수 있다. 응답만 유실된 경우에는 요청별 제출 ID로 커밋 여부를 확인해 성공으로 처리한다. 확인 시점 뒤의 늦은 커밋과 재시도가 겹치더라도 `(form_id, applicant_email)` UNIQUE 제약이 중복 저장을 막고, 이미 제출됐다는 응답을 돌려준다.

답변이 달린 질문은 제목·설명·유형·선택지 값 집합을 바꿀 수 없다 (#98). 단순 오타라도 과거 답변의 의미를 자동으로 판별할 수 없으므로 새 질문을 추가해 이후 지원자에게 적용한다. 질문 표시 순서·필수 여부·선택지 표시 순서는 과거 답변 값을 바꾸지 않아 수정할 수 있다. 관리자 상세와 CSV는 현재 질문 메타를 사용하지만, 이 불변 조건으로 과거 답변의 제목과 값이 보존된다. 제출 배치는 읽은 질문 버전을 양식 행 잠금과 함께 재확인해 편집과 겹친 오래된 답변을 거부한다. 2026-10-14 운영 DB에는 질문과 답변이 모두 0건이어서 기존 데이터 보정은 필요하지 않았다.

배포 순서는 `npm run db:migrate-atomic-application-questions` 실행 후 애플리케이션 배포다. 이 마이그레이션은 기존 질문·답변을 변경하지 않고 버전 컬럼과 저장 함수를 추가·갱신한다.
