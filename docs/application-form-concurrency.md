# 지원서 질문 저장과 제출의 동시성 정책

동시성은 여러 사람이 비슷한 시각에 같은 데이터를 읽고 바꾸는 상황을 말합니다. 지원서에서는 **오래된 관리자 화면이 새 질문을 덮어쓰지 않고, 제출한 답변의 의미가 나중에 바뀌지 않도록** 처리합니다.

## 두 관리자가 질문을 편집할 때

질문·선택지 저장은 `save_application_form_questions`라는 PostgreSQL 저장 함수로 처리합니다. 저장 함수는 여러 SQL 작업을 DB 안에서 한 번의 호출로 수행하는 코드입니다.

함수는 양식 행을 `FOR UPDATE`로 잠그고, 화면이 읽은 `questions_revision`과 DB의 현재 버전을 비교합니다. 잠금은 같은 양식을 바꾸는 작업의 순서를 정하고, 버전은 오래된 화면인지를 확인합니다.

예를 들어 두 관리자가 버전 3을 열었다면 먼저 저장한 작업이 버전 4를 만듭니다. 나중에 버전 3으로 저장하는 작업은 거부됩니다. 질문·선택지 변경과 버전 증가가 함께 확정되므로 중간 실패로 일부 질문만 바뀌지 않습니다.

**저장이 거부되면:** 자신의 입력을 별도로 보존하고 새로고침한 뒤 최신 질문과 비교합니다. 확인 없이 다시 저장해 다른 편집자의 변경을 덮지 않습니다.

## 질문 저장과 지원서 제출이 겹칠 때

제출 액션은 커밋된 질문·선택지를 한 번의 양식 조회로 읽어 입력을 검사합니다. 커밋은 DB가 변경을 확정한 상태입니다. 저장 도중의 빈 선택지처럼 일부만 바뀐 결과를 읽는 방식이 아닙니다.

최종 제출 배치는 `assert_application_form_questions_revision`을 먼저 호출합니다. 이 함수가 양식 행을 잠그고 **양식이 여전히 공개되어 있는지, 읽은 질문 버전과 같은지** 다시 확인한 뒤 제출 정보와 답변을 저장합니다. 따라서 조회 이후 질문 편집이 먼저 확정되었다면 옛 버전의 답변은 저장하지 않고 새로고침을 안내합니다.

질문 버전 확인·제출 정보·답변·요청 제한 기록 연결은 Neon HTTP 원자적 배치로 함께 처리합니다 (#97). 원자적이라는 말은 이 변경들이 모두 확정되거나 모두 취소된다는 뜻입니다. 답변 저장 실패만으로 내용 없는 제출 정보가 남지 않습니다.

응답만 유실된 경우에는 서버가 요청별 제출 ID로 저장 여부를 확인합니다. 저장 결과를 확인할 수 없으면 재시도를 안내하며, 같은 양식의 중복 제출은 DB의 UNIQUE 제약이 막습니다. 사용자는 결과가 불명확할 때 제출 완료 여부를 먼저 확인합니다.

## 이미 답변이 있는 질문

과거 답변의 의미를 보존하기 위해 다음 규칙을 적용합니다 (#98).

| 변경할 항목 | 답변이 달린 질문에서 허용 여부 | 이유 |
| --- | --- | --- |
| 제목·설명·질문 유형·선택지 값 | 변경 불가 | 과거 답변이 다른 뜻으로 읽힐 수 있음 |
| 질문 표시 순서·필수 여부 | 변경 가능 | 저장된 답변 값 자체를 바꾸지 않음 |
| 선택지 표시 순서 | 변경 가능 | 같은 값을 다른 순서로 보여 줌 |
| 질문 삭제 | 답변 보호 FK로 제한 | 답변의 근거가 사라지는 것을 방지 |

단순 오타도 과거 답변의 의미에 영향이 없는지 자동 판별할 수 없으므로 제한될 수 있습니다. 바뀐 내용은 새 질문으로 추가합니다. 관리자 상세와 CSV는 현재 질문 정보를 사용하지만, 위 불변 조건으로 과거 답변의 제목과 값이 보존됩니다.

## 배포와 검증

1. [DB 변경 절차](developer/database-change-procedure.md)에 따라 대상 DB를 확인합니다.
2. `npm run db:migrate-atomic-application-questions`로 설치 계획을 확인합니다. `.env` 없이 실행할 수 있으며 DB에는 접속하지 않습니다. `--confirm-apply`도 신뢰된 대상·복구·승인 경계가 없어 접속 전에 차단합니다. 기존 DB에 버전 컬럼과 저장·제출 검증 함수를 한 트랜잭션으로 설치하던 기능은 비활성입니다.
3. 실제 적용은 [#280](https://github.com/yeongseon/hra-website/issues/280)의 검증된 기존 DB 업그레이드 절차가 마련된 뒤 진행합니다. 원본 SQL·로컬 신규 설치 후보의 존재나 격리 함수 테스트 통과를 운영 적용 승인 또는 기존 결합 업그레이드의 검증으로 사용하지 않습니다. 기존에 설치된 함수와 답변 보호 FK는 카탈로그에서 확인하며, 필요한 객체가 없는 DB에는 관련 앱 기능을 배포하지 않습니다.
4. 격리 PostgreSQL 테스트에서 동시 관리자 저장, 편집 중 제출, 실패 후 재시도, 답변이 있는 질문의 제한을 확인합니다.

**정상 결과:** 최신 버전의 저장·제출만 허용되고 실패한 배치의 일부 행이 남지 않습니다. **함수 누락·버전 오류가 예상 밖으로 나타나면:** 운영 데이터를 직접 고치기 전에 연결 DB와 함수 적용 상태를 확인합니다.

## 과거 확인 기록

2026-10-14 운영 DB에는 질문과 답변이 모두 0건이어서 당시 기존 데이터 보정은 필요하지 않았습니다. 현재 데이터 건수나 새 환경의 적용 상태를 뜻하지 않습니다.
