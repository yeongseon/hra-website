# 카카오 이메일 동의와 기존 계정 주소 갱신

이 절차는 운영 담당자가 카카오의 이메일 제공 동의를 설정하고, **이미 카카오와 연결된 HRA 계정의 임시 이메일 갱신**을 확인할 때 사용합니다. 관련 작업은 [#178](https://github.com/yeongseon/hra-website/issues/178)에서 추적합니다.

**임시 이메일(placeholder)**은 카카오에서 실제 이메일을 받지 못했을 때 사용하는 사이트 내부 주소입니다. 메일을 보낼 수 있는 연락처로 취급하지 않습니다. **바인딩(binding)**은 HRA 계정과 카카오 사용자 ID의 연결 정보입니다.

## 1. 적용 전에 확인하기

- 대상 환경이 개발·검증·운영 중 어디인지와 해당 카카오 앱을 확인합니다.
- [카카오 로그인 설정](../KAKAO-LOGIN-SETUP.md)의 기본 로그인 왕복이 가능한지 확인합니다.
- 카카오 앱에서 `account_email`, `profile_nickname`, `profile_image` 세 동의 항목을 사용할 수 있는지 확인합니다. 이메일 동의 항목은 앱의 자격과 권한에 따라 제공 여부가 달라집니다.
- 신규 가입과 기존 계정 갱신을 포함한 이메일 처리 정책, 검토에서 남은 코드 조치와 회귀 검증을 담당자가 확인합니다. 콘솔 설정 완료만으로 이 조건을 충족했다고 보지 않습니다.
- 검증에 사용할 기존 계정과 신규 테스트 계정을 준비하고, 실제 회원 데이터가 외부 기록에 노출되지 않게 합니다.

**동의 항목(scope)**은 로그인 과정에서 사이트가 요청할 정보의 범위입니다. 현재 코드에서 이메일 요청 설정을 켜면 위 세 항목을 요청합니다. 한 항목이라도 허용되지 않았다면 설정을 켜지 않습니다. 앱 자격은 [카카오 이메일 제공 조건](https://developers.kakao.com/docs/en/kakaologin/utilize)을 확인합니다.

## 2. 대상 환경에 적용하기

카카오 콘솔에서 동의 항목을 준비하고 선행 검증을 승인받은 뒤, **해당 환경에만** 다음 값을 설정합니다.

```dotenv
AUTH_KAKAO_EMAIL_SCOPE=true
```

로컬에서는 서버를 다시 시작하고, Vercel에서는 변경한 환경 변수를 사용하는 배포를 다시 실행합니다. 변수 설정과 재배포 절차는 [배포 안내](../DEPLOYMENT.md)를 따릅니다. 현재 운영값이 이 문서만으로 확인되는 것은 아니므로 실제 적용 여부를 운영 기록에 남깁니다.

## 3. 결과 확인하기

| 확인할 경우 | 기대 결과 |
| --- | --- |
| 기존 카카오 계정이 이메일 제공에 동의하고, 카카오 응답에서 주소가 유효·검증됨 | 다시 로그인하면 기존 HRA 계정의 임시 주소가 실제 이메일로 갱신되고 마이페이지에 표시됩니다. |
| 이메일이 없거나 제공에 동의하지 않음 | 기본 로그인과 기존 계정 연결이 유지되는지 확인합니다. 임시 주소를 실제 연락처로 표시하지 않습니다. |
| 동일 이메일을 다른 HRA 계정이 사용 중 | 기존 바인딩으로 로그인하며 이메일만으로 두 계정을 연결하지 않습니다. 기존 임시 주소가 유지될 수 있습니다. |
| 새 테스트 계정으로 가입 | 신규 계정의 이메일 저장 정책과 승인 대기 역할이 별도 검증 조건을 충족하는지 확인합니다. 기존 계정 갱신 테스트로 대신하지 않습니다. |

기존 임시 이메일 갱신의 구현 근거는 `src/lib/auth-signin.ts`와 `src/lib/auth-email.ts`입니다. 카카오가 보내는 이메일은 단순 문자열 외에 유효·검증 상태도 확인해야 하며, 이메일을 사용자 연결 기준으로 사용하지 않는다는 원칙은 [카카오 공식 안내](https://developers.kakao.com/docs/en/kakaologin/common)를 참고합니다.

운영 기록에는 환경·배포·확인 일자, 확인한 경우와 결과, 남은 작업을 적습니다. 콘솔 설정이나 실제 로그인을 확인하지 못했다면 해당 항목을 미완료로 남깁니다.

## 4. 실패했을 때

`invalid_scope`가 반환되면 요청 항목과 앱의 사용 권한·동의 설정을 확인합니다. 해결 전에는 해당 환경에서 `AUTH_KAKAO_EMAIL_SCOPE=false`로 되돌리고 재배포한 뒤 기본 카카오 로그인도 다시 확인합니다.

이 값을 끄는 것은 추가 이메일 요청 범위를 되돌리는 동작입니다. 다른 인증 오류를 해결하거나 이미 저장한 계정 데이터를 되돌리는 동작은 아닙니다. 잘못된 계정 데이터가 확인되면 바인딩을 임의로 변경하지 말고 담당자가 상태와 복구 범위를 검토합니다.

참고: [카카오 로그인 사전 설정](https://developers.kakao.com/docs/ko/kakaologin/prerequisite), [사용자 정보 응답](https://developers.kakao.com/docs/en/kakaologin/rest-api).
