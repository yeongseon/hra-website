# 기존 카카오 계정 바인딩 복구 (#174)

이 절차는 과거에 생성된 일부 카카오 계정의 연결 정보를 복원하는 **DB 운영 작업**입니다. 일반적인 로그인 실패 해결이나 신규 회원 연결에 사용하는 명령이 아닙니다.

#67에서 이메일 일치만으로 소셜 계정을 자동 연결하던 경로를 차단한 뒤, 바인딩이 비어 있는 과거 계정은 재로그인이 거부될 수 있습니다. **바인딩(binding)**은 HRA 계정과 외부 로그인 제공자의 사용자 ID를 연결하는 정보입니다.

과거 코드는 카카오가 이메일을 제공하지 않을 때 인증 응답의 사용자 ID로 `kakao_<카카오 사용자 ID>@oauth.placeholder` 형식을 만들었습니다. `scripts/migrate-backfill-kakao-legacy-bindings.mjs`는 이 과거 형식을 근거로 제한된 복구를 수행합니다.

## 1. 대상과 중단 조건 이해하기

스크립트는 다음 세 필드가 모두 비어 있는 계정을 조회합니다.

- `password_hash`: 비밀번호 해시
- `oauth_provider`: 외부 로그인 제공자
- `oauth_provider_account_id`: 제공자가 부여한 사용자 ID

조회 결과의 이메일이 **모두** `kakao_<숫자>@oauth.placeholder`와 정확히 일치해야 진행합니다. 다른 형식이 하나라도 있으면 그 행만 건너뛰는 것이 아니라 전체 작업을 중단합니다. 카카오 ID가 중복되거나 이미 연결된 계정과 충돌해도 중단합니다.

일반 이메일이 같다는 이유로 계정을 연결하거나, 다른 소셜 제공자의 계정을 복구하는 기능은 없습니다.

## 2. 읽기 전용으로 점검하기

담당자가 대상 DB·백업·복구 방법을 확인하고, 승인된 대상 환경의 `.env`를 준비합니다. 다음 명령은 **읽기 전용**이며 계정을 변경하지 않습니다.

```bash
node --env-file=.env scripts/migrate-backfill-kakao-legacy-bindings.mjs
```

출력된 후보 수와 중복·충돌 검사 결과를 확인합니다.

- 후보가 **0개**라면 적용할 작업이 없습니다. 여기서 종료합니다.
- 후보가 있으면 해당 계정이 실제 과거 생성 대상인지 담당자가 확인하고 현재 건수를 기록합니다.
- 형식·중복·충돌 오류가 있으면 원인을 조사합니다. 통과시키기 위해 계정 값을 임의로 고치거나 검사 코드를 제거하지 않습니다.

과거 운영 기록의 건수를 그대로 재사용하지 않습니다.

## 3. 확인한 건수로 실제 적용하기

검토한 후보 수가 양의 정수일 때만 실제 적용합니다. 아래 `<확인한-양의-정수>`는 실행 전에 숫자로 바꾸는 자리이며 그대로 입력하지 않습니다.

```bash
node --env-file=.env scripts/migrate-backfill-kakao-legacy-bindings.mjs --apply --expect=<확인한-양의-정수>
```

`--apply`는 DB 변경을 허용하고, `--expect`는 검토한 건수와 현재 DB가 같은지 확인합니다. `--expect=0`은 적용 명령에서 허용하지 않습니다.

적용 직전에는 복구용 계정 ID와 이전 바인딩 상태를 제한된 권한의 로컬 임시 파일에 저장합니다. 파일명은 `hra-kakao-binding-...` 폴더 아래 `previous-bindings.json`이며, 이메일·이름은 기록하지 않습니다. 전체 DB 백업을 대신하는 파일은 아닙니다.

그다음 하나의 PostgreSQL `DO` 문에서 후보·충돌·건수를 다시 확인하고 바인딩을 갱신합니다. **이 SQL 문 안에서 오류가 발생하면 그 문장의 변경 전체가 롤백됩니다.** SQL 성공 이후에는 별도 조회로 결과를 검증합니다. 이 사후 조회에서 오류가 나거나 프로그램이 종료되면 이미 DB 변경이 적용되었을 수 있으므로, 모든 오류를 자동 롤백으로 해석하지 않습니다.

## 4. 적용 결과와 실패 상태 확인하기

정상 완료 후 읽기 전용 명령을 다시 실행해 미연결 후보가 0개인지 확인합니다. 실제 기존 카카오 계정으로 로그인하여 기존 HRA 사용자로 연결되는지도 확인합니다.

운영 기록에는 대상 환경, 실행한 코드 버전, 검토·적용 건수, 사후 확인 결과와 복구 파일 보관 위치를 남깁니다. 공개 이슈에는 개인 식별 정보나 복구 파일 원문을 올리지 않습니다.

사후 검증 실패나 연결 중단이 있었다면 먼저 현재 바인딩과 백업을 확인합니다. 적용 여부를 모르는 상태에서 쓰기 명령을 반복하지 않습니다. 담당자가 복구 필요성과 이후 변경과의 충돌 가능성을 검토한 뒤 처리합니다.

복구 파일은 실제 로그인 확인과 필요한 보관이 끝난 후 운영 정책에 따라 정리합니다.

## 과거 운영 기록

2026-10-13 운영 적용 기록에는 정확한 형식의 미연결 카카오 계정 **10개**를 복원했고, 사후 읽기 전용 점검에서 **0개**, 기존 사용자 로그인 성공을 확인했다고 남아 있습니다. 이는 당시 결과이며 이번 문서 검토에서 운영 DB나 실제 로그인을 다시 확인한 기록은 아닙니다.
