# 사이트 실행하기 — 개발 화면 확인하기

[프로젝트 설정](clone-and-setup.md)을 마쳤다면 개발 서버를 실행하고, 화면과 데이터 연결을 나누어 확인합니다.

## 1. 개발 서버 시작하기

터미널에서 `package.json`이 있는 `hra-website` 폴더로 이동해 실행합니다.

```bash
npm run dev
```

터미널에 준비 완료 메시지와 접속 주소가 나오면 그 주소를 브라우저에서 엽니다. 기본 주소는 [http://localhost:3000](http://localhost:3000)입니다. 포트가 사용 중이면 다른 주소가 출력될 수 있으므로 터미널의 실제 주소를 확인합니다.

서버가 준비되었다는 메시지는 프로그램이 요청을 받을 수 있다는 뜻입니다. DB 조회나 소셜 로그인까지 성공했다는 뜻은 아닙니다.

## 2. 기본 화면과 연결 확인하기

| 확인할 것 | 확인 방법 | 기대 결과 |
| --- | --- | --- |
| 공개 화면 | 홈 페이지를 엽니다. | 화면이 표시되고 터미널에 DB 연결 오류가 없습니다. 개발 DB에 콘텐츠가 없으면 빈 목록이 나올 수 있습니다. |
| 로그인 화면 | `/login`을 엽니다. | 화면이 표시됩니다. 설정한 소셜 로그인 제공자만 버튼이 보입니다. |
| 비로그인 접근 제한 | 로그아웃한 브라우저에서 `/resources`를 엽니다. | 자료가 공개되지 않고 로그인 안내로 이동합니다. |
| 비밀번호 로그인 | 담당자가 준비한 개발용 관리자 계정으로 `/admin/login`에서 로그인합니다. | 관리자 화면으로 이동합니다. DB의 계정·요청 제한 함수 준비가 필요합니다. |
| 소셜 로그인 | 설정한 제공자를 `/login`에서 선택합니다. | 로그인 후 계정에 허용된 화면으로 이동합니다. 새 소셜 계정은 승인 대기 상태인 `PENDING`입니다. |

소셜 로그인에는 서비스 콘솔의 콜백 주소 등록도 필요합니다. **콜백(callback)**은 외부 로그인 서비스가 인증 결과를 돌려보내는 주소입니다. 카카오는 [설정 가이드](../KAKAO-LOGIN-SETUP.md)를 따릅니다. 아직 로그인 설정을 준비하지 않았다면 그 검사는 미확인으로 남깁니다.

## 3. 작은 화면을 만들어 저장 반영 확인하기

실습도 별도 **브랜치**에서 합니다. 브랜치는 검토할 변경을 `main`과 구분해 기록하는 작업 흐름입니다. 진행 중인 수정이 없는지 먼저 확인합니다.

```bash
git status --short
git switch -c docs/first-run-practice
```

기존 변경이 보이면 먼저 해당 작업의 담당자와 정리합니다. 이후 `src/app/(public)/hello/page.tsx` 파일을 만들어 다음 내용을 넣습니다.

```tsx
export default function HelloPage() {
  return (
    <main className="mx-auto max-w-3xl p-6">
      <h1 className="text-2xl font-bold">개발 환경 확인</h1>
      <p className="mt-4">내 컴퓨터에서 실행한 실습 페이지입니다.</p>
    </main>
  );
}
```

파일을 저장하고 실행 중인 주소의 `/hello`를 엽니다. 문구를 한 번 바꿔 저장한 뒤 화면에도 반영되는지 확인합니다. `(public)`은 코드 정리용 폴더 이름이어서 주소에 포함되지 않습니다.

실습 파일을 팀에 제출할 필요는 없습니다. 제출하려면 실제로 필요한 변경인지 확인하고 [협업 절차](../contributing/workflow.md)에 따라 PR을 만듭니다. **PR(Pull Request)**은 브랜치의 변경을 검토하고 병합해 달라는 요청입니다.

## 4. 서버 종료하고 다시 시작하기

개발 서버를 실행한 터미널에서 `Ctrl + C`를 누릅니다. 다시 시작할 때는 같은 프로젝트 폴더에서 `npm run dev`를 실행합니다. 설정 파일을 바꿨을 때도 서버를 다시 시작하고 결과를 확인합니다.

화면이 잘 보이면 다음으로 [개발 가이드](../GUIDE.md)에서 수정할 기능의 위치를 찾습니다. PR 제출 전 검사는 [빌드·배포 가이드](../contributing/build-and-deploy-safety.md)를 참고합니다.

## 막힐 때

| 증상 | 확인할 것 |
| --- | --- |
| 기본 포트가 사용 중 | 이전에 실행한 개발 서버가 있는지 확인합니다. 다른 프로그램을 임의로 종료하지 말고 출력된 접속 주소를 확인합니다. OAuth를 시험한다면 콜백 주소도 실행 포트와 일치해야 합니다. |
| `Module not found` | 올바른 폴더인지, `npm ci`가 성공했는지 확인합니다. 패키지가 선언되지 않은 코드 문제일 수도 있으므로 설치를 반복해도 같으면 오류 파일을 확인합니다. |
| 화면에서 DB 오류 | `DATABASE_URL`의 연결 대상과 필요한 테이블·함수 적용 상태를 확인합니다. |
| 로그인 버튼만 보이고 로그인은 실패 | 키 설정, 콜백 주소, 사용 중인 환경을 확인합니다. 버튼 표시는 외부 인증 성공을 보장하지 않습니다. |
| 저장한 내용이 안 보임 | 저장 여부, 수정한 경로와 브라우저 주소, 터미널의 오류를 확인합니다. |

도움을 요청할 때는 실행한 명령, Node.js 버전, 오류가 난 파일과 메시지를 함께 적습니다. 비밀번호·토큰·DB 접속 주소와 실제 회원 정보는 제거합니다.
