# 화면부터 DB까지 따라가기

사이트를 실행했다면, 다음 목표는 “이 화면을 바꾸려면 어떤 파일을 읽어야 할까?”를 알아내는 것입니다. 공지사항을 예로 들어 **화면 표시**와 **내용 저장**의 흐름을 구분해 봅니다.

## 1. 브라우저와 서버

브라우저는 사용자가 보는 화면과 클릭을 처리합니다. 서버는 요청을 받아 로그인 상태와 권한을 확인하고, 필요한 데이터를 읽거나 저장합니다.

DB(데이터베이스)는 사용자·공지 제목·작성일처럼 구조가 있는 데이터를 보관합니다. Blob 저장소는 이미지·PDF 같은 파일 원본을 보관합니다. 제목을 DB에 저장하는 것과 이미지 파일을 업로드하는 것은 서로 다른 작업입니다.

| 알아야 할 위치 | HRA에서 하는 일 |
| --- | --- |
| `src/app/` | URL에 맞는 화면이나 요청 처리 함수를 선택 |
| `src/components/` | 버튼·표·입력창처럼 화면에서 재사용하는 부분 |
| `src/features/notices/` | 공지 작성·수정 등 공지 기능의 처리 |
| `src/lib/db/` | DB 연결과 저장 구조 |
| `src/lib/`의 권한·파일 모듈 | 로그인·권한 검사와 파일 처리 |

폴더 전체 설명은 [현재 구조 안내](../GUIDE.md)에 있습니다.

## 2. 공지 목록을 읽는 흐름

1. 사용자가 공지 URL에 들어갑니다.
2. `src/app/`의 해당 페이지가 공개할 데이터를 조회합니다.
3. 서버는 결과를 화면에 필요한 값으로 정리합니다.
4. React 컴포넌트가 제목·날짜·목록을 표시합니다.

목록의 색상만 바꾸려면 화면 코드를 먼저 봅니다. 어떤 글을 공개할지 바꾸려면 조회 조건과 공개 상태를 함께 봅니다. 화면에서 숨기는 것만으로 데이터를 보호할 수는 없습니다.

현재 코드에는 페이지나 서버 액션에서 DB를 직접 호출하는 기존 기능과, 서비스로 기능을 나눈 학사 영역이 함께 있습니다. 앞으로 새로 만들거나 재편하는 기능은 [목표 아키텍처](../developer/platform-architecture.md)의 서비스·저장소 경계를 따릅니다. 아직 없는 `apps/web` 폴더를 현재 코드에서 찾을 필요는 없습니다.

## 3. 관리자가 공지를 저장하는 흐름

| 순서 | 확인할 질문 | 코드에서 찾을 단서 |
| --- | --- | --- |
| 입력 | 어떤 값을 보내는가? | 폼, `FormData`, 입력 필드 |
| 권한 | 이 사용자가 이 작업을 해도 되는가? | `requireAdmin` 등 서버 권한 검사 |
| 검증 | 제목·본문·파일 참조가 허용된 값인가? | Zod 스키마, 파일 검증 함수 |
| 저장 | 관계와 중복 규칙을 지키며 저장되는가? | 기능의 서비스·DB 호출·제약 |
| 응답 | 성공 또는 실패가 화면에 어떻게 전달되는가? | 반환값, 오류 메시지, redirect, 캐시 갱신 |

브라우저 입력 검사는 사용자에게 빠르게 안내하기 위한 것입니다. 서버는 전달받은 값을 다시 확인해야 합니다. 인증은 **누구인지 확인하는 일**, 인가는 **그 일을 할 권한이 있는지 확인하는 일**입니다.

한 기능을 수정할 때 위 흐름 전체를 읽되, 수정 범위를 작게 잡습니다. 버튼 문구를 바꾸는 PR에 DB 구조 변경을 함께 넣으면 무엇을 검토해야 하는지 불분명해집니다.

## 4. 파일 업로드는 단계가 나뉩니다

파일을 선택했다고 제출이 끝난 것은 아닙니다. 업로드 허가를 받고, 저장소에 파일을 보내고, 서버가 저장된 파일을 검증한 뒤, 글이나 제출 기록과 연결하는 단계가 있습니다.

학사 개인 과제는 최종 제출 결과를 다시 확인해야 합니다. 화면이 멈췄을 때 새 제출을 계속 만드는 대신, 해당 기능이 제공하는 재조회·재시도 안내를 따릅니다. 자세한 계약은 [과제 제출 범위](../ASSIGNMENT-SUBMISSION-SCOPE.md)에 있습니다.

홈페이지 관리자의 자료 업로드 권한과 학생의 개인 제출 권한도 구분합니다. `ADMIN` 역할만으로 학사 운영 권한을 얻는 것은 아닙니다.

## 5. 오류를 읽는 순서

| 막힌 단계 | 먼저 확인할 것 | 기록할 정보 |
| --- | --- | --- |
| 의존성 설치 | Node 버전, lockfile, 다운로드 오류 | 실행 명령과 오류 요약 |
| 개발 서버 시작 | 필요한 설정과 포트 | 사용한 개발 환경, 오류 단계 |
| 페이지 조회 | 경로, 로그인 상태, DB 준비 | 기대한 화면과 실제 응답 |
| 저장 | 입력값, 권한, DB 제약 | 재현 순서와 표시된 오류 |
| 파일 처리 | 기능이 허용한 형식·크기, 단계별 결과 | 파일 내용 없이 형식·크기와 실패 단계 |
| CI·빌드 | 실패한 job과 첫 원인 오류 | 커밋·검사 이름·재현 명령 |

비밀번호·토큰·세션 쿠키·실제 학생 자료는 기록에 넣지 않습니다. 오류를 없애려고 권한 검사나 DB 제약을 먼저 지우지 말고, 실패한 전제를 찾아야 합니다.
